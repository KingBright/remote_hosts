## 本轮实际改动

### RH-012：等待资源不再占满同类执行名额

执行端先校验工作区与授权、等待写锁或终端输入锁，再取得执行许可。真实阻塞文件操作持有执行许可和写锁直到其结束，不因异步观察者退出提前释放。

轮询端在启动 worker 前登记工作区规范路径或终端输入资源。下一次取任务前，解析同目录别名及父子目录，向网关提供仅针对本设备的临时资源筛选。网关在原子领取前跳过这些暂不可运行的写入或输入任务，不将它们领取到本地占满 worker。普通终端启动、读取和取消不受输入资源筛选影响。

资源释放后通过完成回执通知唤醒已有轮询；短的有界空响应促使客户端重新计算筛选条件，不取消已派发任务。筛选是调度提示，不替代原有权限、版本、幂等和资源锁。旧 Agent 不发送字段时保持旧协议行为；新 Agent 要求网关声明 `resource_dispatch_protocol=1`，部署顺序仍为网关优先。

边界：这不是完整的加权轮转调度；任意持续到来的父子资源冲突仍需公平性测量。若一次筛选涉及超过 1,024 个工作区别名，采用有界的暂停写领取策略，读取和控制仍可运行，不静默使用不完整列表。网络往返、外部文件修改、未由本服务协调的进程不在资源提示的强保证范围内。

两项修复前测试均实际失败：两个同根写等待挡住独立项目；同根及别名积压24项时独立项目无法出队。第一版修复让独立项目成功，但旧筛选条件导致积压队列释放后恢复慢，随后补了回执唤醒，不放宽8秒恢复测试窗口。证据：`target/iteration-033-g/contention-baseline.log` 与 `focused.log`。

### RH-022：不再把前1,000条状态当完整历史

Store 增加有界 keyset 分页及 next_key。旧 list 超过1,000条明确报 state_list_truncated，不再静默截断。终端恢复改为一条针对全部 running/starting 记录的原子SQL更新，不依赖遍历历史分页。只改变恢复状态，保留其它字段；不会因此声称已找回失去的进程或输出。

测试覆盖1,105条记录的完整分页，以及排在前1,000条之后的两个活动终端的恢复。分页本身不声称是跨并发修改的全局事务快照。

## 已落地的改造

### 1. 稳定回连必须持续前进

`scripts/agent_upgrade_support.py` 不再允许对同一份旧快照重复采样后就判定稳定。身份窗口内必须看到网关 last_seen 前进；要求新协议时，read/write/transfer/terminal/control 五个通道均需产生新的真实轮询确认。

同时核对当前 PID、启动时间、版本、会话和前一次会话；拒绝过期/未来时间的观测以及缺失通道。允许小幅时钟差，但不能把明显失真的时间当作就绪。`/device/readiness` 增加 `Cache-Control: no-store`，未来时间记录不再被判为 ready。

更新器观察接口本身不领取业务任务、不续租、不伪造 Agent 心跳。控制面就绪与真实文件/终端功能验收仍是两个门禁，不能混为一谈。

### 2. 一次性启动入口有可恢复证据

`scripts/launch-code-upgrade.py` 采用明确的一次性 plist，不使用保活或周期触发。准备阶段通过临时目录原子发布完整快照，身份包含候选、辅助代码和解释器；启动前重新核对脚本、plist 和候选内容。

独占启动意图防止自动重复 bootstrap。超时或被中断会保存 `bootstrap_outcome_unknown`，启动失败和无法执行分别记录，不把“可能提交成功”写成确定失败后盲目重跑。CLI 不再把明确失败返回成成功退出。

已有相同哈希不重启、升级互斥、独立历史回执和失败回退继续保留。回退后的稳定观察也需要新的会话，而不是拿旧记录来凑条件。候选版本查询及配置检查增加有界超时。

### 3. 验证器不能误报或复用不匹配证据

`scripts/check-code-source.py` 改为固定门禁、逐阶段持久回执。开始执行前先独占领取报告路径，已有回执不会被覆盖，也不会在全部测试跑完后才发现报告重名。

输入指纹覆盖工作区 crate、路径依赖、测试夹具、Cargo/工具链配置及 Python 辅助代码；新增、删除文件同样使旧证据过期。打包工具复用相同输入集合判断，补齐“只核对旧文件而漏掉新增文件”的缺口。

Python 的失败/错误/跳过数分别统计。命令无法启动、测试失败、超时、中断、未完成和输入过期明确区分。POSIX 超时会清理该次验证拥有的进程组，并保留日志，不只结束 cargo 父进程。刻意脱离该进程组的后代和不可拦截的 SIGKILL 不在此保证内。

`--check-receipt` 只比较当前输入与报告，不运行检查命令。检查命令采用锁定依赖，不再先静默修改 Cargo.lock 再把变化藏到新基线里。

## 使用中遇到的限制

本轮六次原生文件上传均完成并核对哈希，包含版本检查的文件替换；其中一次由工具内部重试后完成。这是实际文件交接观察，不是吞吐或 token 节省基准。

两项工具调用在执行前被平台拦截：旧版双设备公网验收，以及定位最终输入变化的诊断。没有执行或通过这两项，不能据此关闭发布和全部设备验收。

当前工具目录的参数能力与线上实现仍可能不同；未使用旧目录未声明的新参数。Mac Studio 的升级结果仍需按发布记录独立取证，本轮不把“启动请求已提交”当成完成。

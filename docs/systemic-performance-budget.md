# 系统性性能优化：减少工作量，再降低单位成本

状态：设计与实测基线已建立；本文件不是已实现或已部署的性能声明。
基线版本：0.10.15，源码提交 8ec2ef8761fadd0b2e1e4bd3951e1a3da3ef2b44。

## 1. 决策与边界

性能优化分两条主线：减少不必要的操作次数、数据量和保留时间；降低剩余必要操作的等待和执行成本。二者必须共同验收，不以版本号、测试总数或少量快样本代表性能完成。

优先顺序：删除不必要工作 → 复用已有结果 → 合并重复工作 → 缩小传输与存储内容 → 优化剩余热路径 → 依据瓶颈实测调整硬件或存储技术。

不可削弱的能力：授权与撤销、工作区隔离、幂等冲突检测、原操作绑定、关键执行事实的持久性、结果原子提交、断线后观察原任务而非重放命令、故障与证据缺口的明确报告。不得将内存中尚未提交的事实标为 durable。

同一业务结果不应因为查询次数增加而被复制保留多份。可追溯不等于每次轮询都必须在主数据库同步写两次、永久留一张几乎相同的收据。

## 2. 本轮实测基线

生产盘点只使用只读连接，查询设置时间上限，未修改配置、触发 checkpoint、清理数据或降低持久化等级。

## 3. 数据分级，而不是对所有数据一律同步永久保存

| 数据类别 | 持久化与保留方向 | 必须保持的边界 |
| --- | --- | --- |
| 安全和执行事实 | 原操作身份、授权变更、幂等键及参数指纹、执行接受与终态、必要传输检查点；相关字段一次事务提交 | 向调用方确认关键动作前先持久化；重启后不重复执行 |
| 查询与展示快照 | 正常查询引用原始事实，优先直接读取；本次 request_id 作为链路标识，而非新增操作事实 | 每次查询仍验权；不能伪造该次查询已持久化 |
| 进度和在线遥测 | 有界内存最新值、变化触发、有限周期合并；启动后未重建的新鲜度明确未知 | 会话身份、租约安全续期、授权撤销不能按普通遥测延迟 |
| 日志和大结果 | 一份不可变证据正文加哈希/游标/引用；热索引保存恢复所需信息，不复制多份完整正文 | 引用必须可读、可校验且受同等权限保护；未完整归档不删除原证据 |
| 历史与统计 | 热历史分页、有界清理；性能直方图与计数聚合，不逐轮写一份监控历史 | 未结束、结果未知、暂停传输和未解决故障不得过期；幂等保护不能随正文清理消失 |

正常查询、原命令失败、查询本身失败须区分。例如原命令 exit=7 已经有完整回执，重复观察无需再复制这次失败；新的授权拒绝或存储失败则有独立诊断价值。异常突发保留首末证据、精确计数和有界细节，明确限额，不用无限错误日志造成第二次故障。

## 4. 首项实现：观察路径不再制造业务写入

范围先限定为确实不创建任务、不改变授权或传输状态的 Gateway 观察路径。不得只根据工具名称或 readOnly 注解推断；operation_get 的旧 Agent 输出补取、下载链接续签等兼容路径需要单独审计。

目标：普通成功观察以及无变化观察不新增 jobs、不复制结果、不在业务数据库同步持久化开始/结束两份请求状态。查询链路仍提供 request_id、原 operation_id、时间、原事实版本/游标和下一步。

必须拆开以下事实，不能继续复用一个含义混杂的 durable 布尔值：
- 被观察的业务事实是否已持久化。
- 本次观察的请求记录是否已持久化以及保存在哪里。
- 输出是否采集完整、当前响应是否包含全部输出。

无变化响应仍保留原命令失败、stale、truncated、结果未知、人工动作和禁止重放规则。无法从 request_id 找到单独保存的观察记录时，应报告未保留/不可确认，并提供原操作证据边界，不能报告命令未执行。

升级契约与测试后再启用新默认；不能在实现不变时仅将工具改标为只读，也不能悄悄把需要完整查询审计的场景降级为采样。

## 5. 其余减法

- 在线心跳与业务进度分别处理。时间戳变化本身不使整个快照变脏；业务终态与故障立即传播，重复完成快照和空回执队列不反复落盘。
- jobs.result、terminal_observation、请求回执和 Agent 完整日志盘点重复内容。跨机器容灾副本有价值，必须保留；同一节点只为不同视图重复存正文则应删除重复设计。
- 活跃任务查询与历史查询分开。LIMIT 100 不代表只扫描 100 行；用真实查询计划验证，不先拼全量历史再截断。
- 清理按批次、时间和字节预算推进。先验证过期索引的收益及写放大，必要时仅索引可过期记录；避免每次清理扫描永不过期的证据全集。
- TTL、归档和回收策略按数据类别定义，不能临时执行全库 DELETE/VACUUM 来制造好看的基准。已有证据的迁移与清理另走可恢复步骤。

## 6. 降低必要操作的单位成本

保持 SQLite WAL 与关键事务 FULL 持久化。先测连接等待、写锁等待、SQL 执行、COMMIT 同步和 checkpoint，不能把它们合成一个 SQL 慢耗时后猜测根因。

审查同步边界：同一原子事实的写入放进同一短事务；事务中不等待网络、文件上传或模型结果。必要时采用有界单写者调度/合并提交，队列有上限且公平，不额外引入一套任务数据库；必须提交成功后才确认成功。

根据查询计划调整热查询和索引，限制 JSON 大字段的反复解析。读池与写入排队分别观测，不通过无限增加连接数让更多写操作互相等待。

在相同卷的独立临时文件/数据库测试同步写延迟，并核对实际挂载、介质和宿主负载；未确认前不把 NAS、机械盘、容器或网络挂载视为原因。若设备介质确为瓶颈，再使用合适的本地持久化存储；RAM 盘不能充当执行回执的持久层。

## 7. 统一适用于其他模块

| 模块 | 降低单位成本 | 减少工作量 |
| --- | --- | --- |
| 网络 | 复用连接、改善路由和有界等待 | 合并状态请求、变化通知、只传增量、不重复目录与日志 |
| CPU | 减少分配、解析和不必要拷贝 | 结果投影一次计算多入口复用；无变化不重算 |
| 磁盘与日志 | 顺序追加、受控批次提交 | 正文只存一次；遥测聚合；旧热数据有界 |
| 页面 | 批量查询、关键查询索引 | 活跃优先、历史分页、增量卡片、展开时读详情 |
| 构建与发布 | 本机交叉编译、缓存和增量构建 | 冻结一次源码；已验制品复用；传输中断不重新编译 |
| 工具输出 | 精确结构化提取 | 默认变化摘要和证据引用；不确定性、退出码和恢复边界不能压掉 |

## 8. 验收预算与测试矩阵

以下是下一阶段门槛，不是已经实现的性能数据。

1. 100 次正常/无变化的 Gateway 观察：业务数据库持久写入为 0、远端任务新增为 0；trace 与原结果身份可核对。需要完整审计的模式单列开销，不暗中牺牲审计。
2. 同一已完成结果被观察 N 次：结果正文仍只有一份，历史正文不重复返回，热库增长不随 N 复制原结果。
3. 四节点空闲 30 分钟：分别记录每节点/每通道请求数、业务写入、状态快照事务、WAL 字节、CPU 与后台唤醒；普通状态快照持久化初始目标不超过每设备每 30 秒一次，实际变化与安全状态另计。
4. 执行一次短命令：列出从请求接受到结果读取的全部 SQL 写入、事务和字节预算；关键接受/终态分别原子提交，不因轮询次数增加关键结果写入次数。
5. 并发 1/4/16 的真实负载，外加 0/5/20 个观察者：分别报告中位数、P95、P99、超时和失败样本。批量与异步不得让尾延迟、背压或错误可见性变差。
6. 热库 1 万/10 万条合成历史对比：活跃操作查询与清理有界；执行 EXPLAIN QUERY PLAN，记录实际扫描范围和额外索引写入。
7. 隔离故障：写锁争用、慢磁盘模拟、提交失败、断网、重启、慢消费者、重复回执。关键事实不丢、未提交不假成功、原命令不重复、恢复不绕过授权。
8. 线上最终回归沿用已有四机 read/edit/execute/transfer/recovery 用例。短命令健康网络下 P50 目标 2 秒、P95 目标 5 秒；采样量与环境必须公开，不能拿少数样本宣称分位数达标。

## 9. 落地顺序

A. 本轮完成的只读盘点与原生写入计数形成基线，补齐 idle/observer-load 指标。
B. 优先交付观察请求回执分级与同一事实去重，测试授权、错误、重启恢复与存储边界。
C. 交付状态写入合并、热冷历史与有界清理，再优化必要事务、索引和提交调度。
D. 同源本机构建、原生故障注入、节点升级、真机 A/B；没有通过成本预算和恢复测试就不宣布完成。

参考：SQLite 官方 WAL 文档说明 WAL 同时只有一个写者、FULL 提交需要同步、自动 checkpoint 可能使部分提交变慢。这些机制是测量方向，不是本现场全部延迟的已确认根因。

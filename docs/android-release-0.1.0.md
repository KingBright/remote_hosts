The integration fixture uses a separately built debug agent, a dedicated Android 15 / API 35 ARM64 emulator, a private test CA and a real isolated `remote-hosts-code 0.10.24` gateway. It verifies TLS registration, screen structure, password redaction, Unicode input, fresh-observation enforcement, changed-screen action verification, screenshot and file byte integrity, overwrite refusal, authenticated UID 2000 shell activation, idempotent mutations, file pull, and local stop.

The exact signed release APK is transferred and installed through that shell bridge, checked byte-for-byte, then launched and observed in the foreground. Its secure configuration window is not captured. **The complete remote-control fixture runs through the debug agent; release installation/launch smoke tests are separate. This is not a physical-phone or production-release-connection acceptance claim.**

## Build and fixture recovery

The first rebuild ended with an unexpectedly terminated Gradle daemon. A subsequent build using the installed Homebrew HotSpot JDK 17 succeeded. The build machine was under substantial memory pressure; this observation alone does not establish the daemon's root cause.

A separate test attempt stopped during ADB installation. Emulator crash logs showed `system_server` aborting with an ART suspension timeout. Only the dedicated test emulator was reset. The final successful run used four virtual cores, 4096 MiB memory and host GPU rendering. No physical phone was reset, no unrelated project process was stopped, and no assertion was removed or weakened to obtain a pass.

## First-install workflow and boundaries

See `android-install-zh.md` for JSON import, local consent, accessibility and shell activation. A phone needs its own independently revocable gateway enrollment. Any production enrollment is a separate administrative action and receipt, not part of the isolated integration result.

The first release provides on-demand screenshots rather than continuous video, 64 MiB file transfers, and an optional built-in shell helper activated through authorized ADB. It does not include in-app wireless ADB pairing, automatic Root or Device Owner provisioning, security-window bypasses, or a claim of unlimited unattended operation. OEM permission behavior, background lifetime, reboot recovery and the owner's physical phone remain to be verified.

## 实现

### 独立且保守的保活

`agent_liveness.rs` 提供独立连接池的保活协程，只读取有界内存中的设备会话、活动任务及进度。它不扫描 SQLite、不读取终端日志、不等待回执统计、不伪造 poll lane readiness。

每两秒检查，距离最近已证实的请求发出时间达到十秒才需要补发；单次网络请求预算八秒。长轮询收到迟到响应时，按请求发出时间保守计算租约，不把响应到达误当作刚刚续租；乱序响应不会覆盖更新的已确认联系。启动时 heartbeat 先于 poll 认领 session 的 409，只有后续成功的鉴权往返才能解除其普通退避；显式 Retry-After 和鉴权拒绝仍被遵守。

传输错误后重建轮询/保活连接池，并设置连接、空闲连接、TCP/HTTP2 保活参数。保活只向原配置的网关和原设备会话发送观察请求；不自动切换设备、不重放终端命令、不迁移回执的授权目的地。公网物理链路完全不可达时仍应如实离线。

### 减少数据库与文件读取

`terminal_sync_recent` 是仅 Agent 安装、仅 terminal 行参与的部分索引；其 kind 前缀和排序表达式与实际查询一致。查询计划测试要求命中该索引且没有临时 B-tree，避免索引存在但被查询规划器忽略。

终端快照增加可丢弃的内存缓存：空闲且无新终端事件时最多三十秒刷新一次；有运行中终端或完成通知时及时刷新。快照读取预算五百毫秒，失败不伪装成空列表，也不推进成功版本。历史记录和执行证据不删除。

可选回执统计和 poll-health 持久化各设二百五十毫秒等待预算。迟到的 SQLite 遥测写入同时校验运行会话和递增版本，不能覆盖新会话或更新的恢复状态。WAL/FULL 持久化、资源锁和业务回执的正确性约束不降低。

## 查询微基准

Mac Studio 上隔离内存 SQLite、10,000 条模拟 terminal 元数据、每阶段 30 次查询：优化前中位 52.0777 ms，优化后 0.0305 ms。优化前存在临时排序，优化后只使用 `terminal_sync_recent`。这是隔离查询微基准，不能宣称生产网络或整机延迟提升相同比例，也不能直接推算原 41 秒锁等待会缩短多少。

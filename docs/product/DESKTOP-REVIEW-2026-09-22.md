补充修复了标准验收器固定回执协议 1 的旧假设，明确接受已支持的协议 1/2 并拒绝未知协议；Windows Python 探针使用适合 PowerShell 的参数编码；幂等比较按原操作的持久证据归一化协议 1/2，不把查询是否留存误判为操作结果变化。协调器可显式选择修复后的验收脚本并记录其 SHA 与原包身份，不覆盖已发布制品。39 项验收脚本回归和 32 项发布客户端回归通过，冻结制品的 752 项验证记录保持原样。

错误 SHA 验收曾因 `gateway_connection` 暂停。现场恢复原 operation 后明确得到 `sha256_mismatch`，目标文件不存在。验收器现仅对已知瞬时连接故障恢复原传输，最多两次；等待新授权、其他暂停或丢失恢复响应时保留原 ID 并停止。拒绝场景必须匹配具体错误原因和目标未改变，不能把网络错误或任意 `error` 当作通过。此修复只覆盖验收器，发布协调器的 RH-009 仍待完成。另一次运行在清理命令提交前遭遇 TLS 握手重置，验收器未重放命令；现复用已有发布客户端的原生持久 MCP 通道和请求回执，避免独立的逐调用 HTTP 实现。传输选择与临时授权撤销结果写入报告。

**扩展标准验收未完成。** MacBook 两轮已实际完成 2 MiB 下载/上传、Range、防覆盖和 SHA 错误拒绝，但未产生完整四机通过报告。最后一轮原生通道运行期间，MacBook 系统负载超过 160、Agent SQLite 查询出现约 38 秒延迟，二进制探针创建命令超时退出 1；Gateway 终端快照还出现本地已超时但暂时仍显示 running 的情况。仅能确认高负载与延迟同时发生，仍须分别定位各层原因。失败回执已保留，任务所属进程已结束，探针文件已按哈希清理；未中断其他任务，也未继续重复验收。

## 下一轮建议

1. **先做时钟容错与明确诊断。** 对设备前后偏移 2 分钟、1 小时进行回归；异常遥测不能让授权设备失联，认证/令牌到期校验仍独立执行。排障应能从单条状态结果确定拒绝边界。
2. **完成发布器的原操作恢复。** 将暂停、等待授权、继续上传、控制响应短暂中断、发布后回执丢失纳入同一验收；增加“仅验收”入口。不得因不确定而新建等价上传、命令或升级。
3. **补足宿主与跨平台故障矩阵。** Codex、ChatGPT、Gemini Spark 分别核对工具 schema、授权刷新、精确编辑、大文件和取消；Windows 执行编码与退出状态独立测试，macOS 保留本机签名与权限连续性。
4. **处理已观察到的负载瓶颈。** 先重现并定位 RH-056，再测低速网络、4 MiB checkpoint、控制请求频率和 SQLite 竞争；记录首字节、吞吐、恢复字节及工具往返次数，避免只增加工具或层次。资源负载恢复后，使用明确的新验收 run-id 再完成扩展四机验收，不能重用已清理探针的旧幂等身份。

`backlog.json` 仍是问题清单事实源。此次只更新有新证据的条目，其他历史状态需要逐项复核。后续 runtime 变更必须产生新版本和新不可变包；本轮文档更新不得覆盖 0.10.19 制品。

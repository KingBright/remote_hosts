# Remote Hosts 0.5.0：协作效率与交付闭环

规划日期：2026-09-11。实施状态更新：0.5.0 已完成固定源码验证、两平台构建并部署到 NAS、MacBook 与 Mac Studio；338 项测试通过。本文保留当时的规划依据和验收目标，实际完成情况以 `docs/releases/0.5.0/RELEASE.md`、`docs/product/BACKLOG.md` 与 `NEXT.md` 为准。

## 决策与范围

建议下一主版本直接集中交付0.5.0，不再把相互依赖的体验问题拆成许多孤立补丁。六个工作包围绕“少调用、能恢复、改动可审查、按设备交付”组织。版本号不是进度，功能/源码/运行/宿主验收分别记录。

规划时的基线是网关/MacBook 0.4.1、Studio 0.4.0。随后本路线图中的独立发布、事件交接、完整 diff、Manifest 同步等主体能力已经进入 0.5.0；首次自动标准验收因为 run-id 格式 bug 未真正执行，该 bug 已修复。不要用本文的历史基线覆盖当前运行事实。

原始规划证据索引仍保留在同目录 `roadmap-0.5.0-evidence.json`，用于解释设计来源，不代表当前版本状态。

## 先补交付基线：源码不能只存在于未跟踪工作树

本次git status确认 `crates/remote-hosts-code/`、发布脚本和测试仍未跟踪。现有固定源码归档有效，不能说没有备份；但main本身不能复现这些已部署的新源码。同时对核心目录调用code_diff得到空字符串，不能把它当成“没有待审查内容”。

发布前按明确白名单审查本项目新增源码、测试与脚本，检查敏感文件、运行状态和缓存排除规则，建立main上的可追溯提交基线。保留用户其他改动，不执行git add -A、reset、force push。当前规划不擅自进行Git写操作。后续发布记录绑定commit、dirty/source snapshot身份、验证回执、产物哈希及运行实例；从干净检出加声明输入可以重建同一源码范围，不宣称跨工具链二进制天然完全可复现。

对应RH-025、RH-048、RH-049。

## 工作包A / P0：按目标独立发布、排空和验收

问题：0.4.1发布编排先等待所有设备变为新版本，Studio忙会让健康MacBook也不能继续自动验收。长时间Agent终端观察还可能成为idle门禁所见的活动任务。

实现边界：保留网关先升级这一协议依赖；之后两台Mac各有独立状态机，分别记录已暂存、等待任务结束、更新器已启动、原回执待到达、就绪、验收、完成/延期/回退。一个目标忙或失败不停止其他目标。汇总保留原目标集合，不能删除延期目标来生成“全部通过”。

排空使用持久维护意图和租约：暂停领取新的修改/终端执行/传输任务，继续允许状态查询、取消、回执补送；已运行任务完成或到达有定义的安全暂停点再切换。超时返回具体阻塞任务，不强杀未知业务。观察原升级回执通过独立更新器状态或短只读查询，不创建等待数分钟的Agent终端。

已完成发布阶段只复查不重装；未知副作用先核对原任务；某个目标回退不撤回健康目标。通用发布入口使用验证过的release_receipts模型，不再为每版临时复制publish.py和finish.py。

验收：A长期忙，B完成升级及现场验收，汇总仍显示A延期；排空时提交新工作行为可解释；发布器在暂存、启动后、回执落盘前分别中断，恢复不重复安装；旧版本不兼容时在切换前拒绝。

对应RH-029、RH-042、RH-044、RH-047。

## 工作包B / P0-P1：统一观察、明确错误与分段耗时

在现有operation_get/terminal_read基础上统一观察模型，避免模型维护“执行操作ID、启动回执、终端ID、读取操作ID”等多层轮询。提交仍保留类型化工具，不造隐藏任意命令的万能execute。

一个原任务观察可按权限返回执行状态、关联终端退出码和增量输出、传输确认偏移、回执投递状态。短任务支持有界合并等待；长任务只查询已有事实。终端输出按稳定字节游标，事件游标与输出游标分开，不让状态哈希冒充历史事件序号。观察不要变成新的持久执行任务。

错误统一到稳定error_code、stage、outcome、safe_recovery_action、trace/operation_id。最低区分未执行、已执行、部分完成、结果未知和需要授权；不把所有失败挤成tool_failed，更不把retryable=true解释为可以重跑shell。

queue/resource_wait/execute/delivery分别由负责该阶段的一侧使用本地单调时钟测量，不能直接相减不同机器墙钟。回执阻塞提供受控的“重新投递原结果”入口，重新检查原设备、原网关和权限；冲突/权限失败不能盲重试。日志不泄漏命令敏感内容或签名URL。

验收：20个任务一次有界观察；快速命令返回退出码和首屏，等待超时不取消/重做；确认丢失后仅补原结果；每类失败附可执行的下一步；旧Agent不支持时明确返回能力缺失。

对应RH-014、RH-016、RH-017、RH-024、RH-039。

## 工作包C / P1：完整变更集与多文件失败恢复

扩展code_diff的覆盖范围：同时列出tracked、staged、untracked、deleted、renamed、binary以及因为预算/过滤而遗漏的内容，标记每种来源。未跟踪文件必须作为新增内容或明确未展开项返回，不能空diff暗示全部无改动。

引入轻量change_set身份，绑定工作区、基线版本、每个文件前后哈希和原操作。复用现有逐文件原子写和预检，不承诺跨多个普通文件路径瞬间全局原子。多文件写入第N项失败时，回执明确applied/pending/conflicted，持久记录每个已提交文件以及最终状态，不只留prepared日志。

中断后按前后内容和发布身份核对，不能凭时间戳或日志缺失自动重放。只有可证明未完成且版本条件仍成立的项才能恢复；用户并发修改保留，无法判断的项明确需要合并。可选验证配置绑定变更集和原验证任务，未成功的文件不能包装成“整批完成”。

验收：本次核心目录的未跟踪内容可被审查；10文件第7个失败后前6项准确记录；重启后不重复副作用；用户修改第3个文件后恢复不会覆盖；新增/删除/二进制以及空目录都有清楚范围说明。

对应RH-019、RH-025、RH-037、RH-048、RH-049。

## 工作包D / P1：跨对话可续接的工作区交接

扩展workspace_context，给出当前任务、阻塞原因、关联变更集、最近验证回执及其是否覆盖当前输入、发布阶段和精简下一动作。工具生成事实，用户/模型写入的目标说明与事实字段分开；不读完整Codex聊天记录当作工程真相。

新增有界、按工作区隔离的持久事件序列，覆盖执行完成、暂停、需要授权、编辑部分完成、验证完成、发布阶段。结果与事件尽量同事务记录。断线后按after_seq补读；序号过期返回cursor_expired与重新取得快照的步骤，不静默丢事件。大日志和产物使用引用，避免每次附送全文。

工作区摘要与设备级维护/队列计数明确区分；观察器本身不污染业务任务时间线。分页在活动状态变化时说明一致性范围。

验收：断线期间20个任务完成，续接不漏完成事件；A工作区游标不能读取B；一次快照加必要补页恢复原任务和验证范围，不靠重新扫描全部聊天或输出一长串日志。

对应RH-015、RH-016、RH-025。

## 工作包E / P1：批量文件交付与存储生命周期

第一版先做受控的单向文件集同步，不做双向冲突解决平台。清单包含相对路径、类型、大小、SHA-256、必要执行权限和目标预期版本。支持include/exclude、预览、只传变化项、整批manifest ID和逐文件结果；复用现有续传、取消和源身份核对。默认不删除目标多余文件。

接收时拒绝绝对路径、..、逃逸符号链接、特殊文件及解包炸弹，限制文件数、单文件大小、声明总大小和实际展开大小。多文件发布遵守C的可恢复规则。内容缓存仅在原授权范围内复用，不能靠猜哈希取得别人文件，不做任意跨租户存在性探测。

同步实现可预览、有界的过期数据回收：区分活动传输、可恢复检查点、完整产物、日志、幂等凭证、阻塞回执。先统计后按租约/代际与拥有关系清理；不只按mtime删除。定时清理无需等下一次新上传触发；该后台维护是待实现的产品功能，本轮没有启动维护任务。

幂等凭证和数据实体分别保留，必要时保留小型完成标记；删除产物后查询返回expired，不让旧副作用因为凭证被清空又能执行。给设备级/工作区级配额和低磁盘错误。现有64 MiB默认先保留，256 MiB作为容量测试通过后的显式协商能力，不只改schema常数。

验收：100文件只改3个时只传3个文件内容，路径/冲突结果准确；中断后恢复相同manifest；两台机器传输时状态和代码操作可进行；10000条历史/过期记录分页清理；活动慢传输和正在下载的对象不被误删；清理后旧命令不被再次执行。

对应RH-007、RH-022、RH-023、RH-032、RH-033、RH-050。

## 工作包F / P1：宿主能力闭环与低开销返回

本次服务端目录报告18项，但本对话发现结果仍为15项且operation_get只接受单ID。这是已观察的暴露差异；不能仅从差异断言唯一原因是缓存，也不能用一个通用代理工具绕过动作启用/授权。

分别记录服务端schema、已启用宿主动作及Agent实际功能；未知客户端hash返回unknown而非compatible。每版生成工具目录差异和原生宿主验收记录；支持list_changed的客户端走标准通知，不支持的按宿主管理能力正常刷新。客户端还没暴露的新增功能必须单独标识，直连MCP通过不能替代原生聊天验收。

补outputSchema和响应预算，默认摘要/必要状态，完整日志按需读取。先测真实宿主读取行为，再选择受支持的紧凑返回策略；现有协议为向后兼容建议同时返回序列化TextContent，不能对所有旧客户端直接删掉那份JSON。对无法确认的宿主保留旧兼容返回，优化正文内容和轮询次数，实际token不可观测时只报告字节及调用数。

验收：新会话中能实际调用本版计划交付的动作；新Gateway/旧Agent、旧Gateway/新Agent、缺失hash、禁用动作均有明确结果；缩减输出不丢字段或改变权限确认；不得声称工具端能取消宿主安全审核。

对应RH-018、RH-030、RH-035、RH-036。

## 交付与度量

推荐执行顺序：先补0.4.1已安装目标验收和源码交付基线；然后A+B修复发布/观察的共同阻塞；C+D形成可审查可交接的工作单元；E+F完成批量成果交付和真实宿主接入。内部可以并行实现独立模块，统一候选冻结后完整验证，不以阶段过多为由增加每次人工确认。

以下是验收目标，不是已测成绩：典型编辑-测试-诊断流程的观察工具调用数相对0.4.1基线下降至少30%；相同100文件清单只改3个时不重复传97个文件内容；20任务完成后一次有界摘要/必要补页可续接；单设备忙不增加健康设备的发布等待依赖。固定样本、网络条件、p50/p95和输出预算一起保存，绝不只比较挑选的一次快样本。

通用门禁：权限隔离、重复请求、并发写入、取消、网络中断、进程重启、磁盘不足、源码变化、回执丢失和宿主声明不一致。完整功能测试与现场测试按原任务计数，不用测试数上涨替代场景覆盖。每个已安装目标独立验收；原选中集合有人未完成时汇总显示partial/deferred，不能宣称全部已验收。

本版暂不优先做完整LSP、任意DAG工作流设计器、复杂监控大屏、全自动改代理/证书、未经容量验证的超大文件或为了凑功能增加大量工具。

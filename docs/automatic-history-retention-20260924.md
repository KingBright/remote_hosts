## 默认策略

| 项目 | 默认行为 |
| --- | --- |
| 启动 | 进程启动后约 30 秒执行首次维护 |
| 常规间隔 | 每轮完成后约 5 分钟再执行 |
| 普通成功历史 | 完成后 7 天进入回收 |
| 失败、取消、超时历史 | 完成后 30 天进入回收 |
| 可回收历史目标 | Agent 设备级、Gateway 网关级分别为 2,000 条或 512 MiB |
| 容量压力 | 优先回收最旧的可回收记录，但至少保护最近 24 小时 |
| 积压追赶 | 已回收但仍超限时约 5 秒继续；每轮容量回收最多 64 条 |
| 失败处理 | 整轮维护失败约 60 秒后重试；单个文件失败保留队列，在后续轮次重试 |
| SQLite | 独立单连接维护池，50 毫秒 busy_timeout，250 毫秒连接获取及事务入场预算；已开始提交不强制取消，业务 FULL 持久化不降低 |

7/30 天是通常的正文保留期，不是容量压力下的最低保留承诺。2,000 条和 512 MiB 是**可回收历史正文的软目标**，不是整个状态目录的硬上限。最近 24 小时、正在运行、结果不确定或尚未确认回传的数据不会为满足配额被删掉。Gateway 的压缩后幂等身份、小型结果摘要、请求关联与未决恢复记录仍保留；本次没有把所有历史元数据都改成有限保留。

## Agent 清理范围

覆盖已封口并可确认完成的终端日志及状态、已完成/失败/取消/过期传输的私有检查点、已确认回执且确实完成的代码编辑恢复日志。终端任务使用完成更新时间计算保留期，不使用可能早很多天的启动时间。对于缺失可靠完成时间的旧记录，先验证实际完成状态和回执归属，再写入独立的“首次确认保留时钟”，不伪造业务完成时间。首次确认当天不删除；从该时间起自动执行相同的 7/30 天及至少 24 小时的容量保护规则。反复扫描不重置时钟，未知或未确认任务不会获得可回收资格。

终端或传输存在 local_operation 时，要求状态为 done、gateway_accepted 为 true 且无保留标记；回传队列存在同操作记录时不回收。过去启动清理已移除的 Gateway 已接管记录可能不存在 local_operation，此时仍校验终端/传输的完成状态。runtime_lost、未知结果、未封口输出、可恢复的活动传输、部分编辑和历史保留标记均不自动删除。

代码编辑同时检查数据库摘要和磁盘日志的 completed 状态、操作 UUID、设备及工作区绑定。取得独占历史访问后再次校验磁盘日志内容指纹，避免选择候选与执行回收之间发生的恢复编辑使旧候选失效；原本不存在的日志后来出现也不会被旧候选删掉。回收后保留原指纹与已确认标志；再次请求恢复时返回 history_expired，不把缺失日志误认为应重新执行代码编辑。

文件路径只由已验证 UUID 和固定内部目录构造。使用 capability-relative 文件访问，拒绝特殊文件、符号链接及链接目录，不扫描或删除项目源码、用户任意文件。清理时对终端历史读取、恢复编辑和显式 workspace_gc 让行。

## 崩溃与并发安全

清理采用两阶段回收，而不是先删文件再假定数据库会提交：

1. 在短事务内再次检查候选内容、生命周期和回执状态，写入文件回收意图，并退休或压缩元数据。
2. 事务提交后删除内部文件；删除成功才移除回收意图。

数据库事务失败不会删除文件。进程在提交后或文件删除后中断，重启后使用原回收意图继续，已不存在的文件视为已清理。回收队列最多保留 128 个项目，避免清理失败本身形成无限队列；单个文件失败不阻止本轮尝试其余项目。

扫描采用每页 64 项的 keyset 分页，删除上一页不会导致下一页跳项。页面之间让出执行资源，不持有覆盖全部历史的写事务。维护与保活、业务查询使用不同连接池。可能读取大编辑日志的候选检查放入阻塞线程池，不在异步执行器上同步解析整份日志。清理只覆盖一条最新运行摘要，不为每个清理周期创建终端或工具任务。

## Gateway 清理范围

Gateway 对已确定完成的旧任务清理大的请求参数、结果正文与终端输出预览，保留授权需要的 owner/device/tool/workspace，以及原操作 ID、幂等键指纹、原始结果摘要哈希。对终端任务，以真实最终退出时间与原任务更新时间的较新值计算保留期。

历史正文不可用时明确返回 history_expired；不会声称已删除的正文仍能读取。回执区分“执行已完成但正文过期”与“执行结果未知”，保留最终退出事实，evidence_complete=false，并明确提示不要重放，而不是要求无限读取已经删除的输出。迟到的 Agent 回执与保留的原结果摘要核对：原样回执仍可确认，冲突结果仍拒绝，其他设备仍无权操作。部分结果、未知结果、活动语义保护和未结束终端不压缩。旧终端心跳不能重新生成已经回收的结果预览。

到期的普通缓存和授权临时记录由维护循环分批回收，不再只依靠之后的新文件传输触发。文件传输产物缓存原有的到期和容量逻辑不在本次改成新的文件扫描器；未决传输和其回执仍受保护。

## 可观测性

Agent 的 workspace_context.workspace_gc 显示 automatic=true、默认策略，以及最近的设备级汇总结果。数据包括扫描数、保留数量和体积估计、保护项、退休记录数、实际文件回收字节、未完成文件回收、条目错误与是否仍超限。该汇总明确是设备级，不暴露其他工作区的详细记录。Gateway 保存同名最新维护状态。

正文保留上限与状态数据库物理文件大小不是同一件事。SQLite 删除行后通常将页面留在 freelist 供后续写入复用；不启用自动真空时，文件不一定立即缩小。本次采用 PASSIVE checkpoint，不在业务在线期间执行完整 VACUUM，以免用清理再次制造长写锁或临时空间压力。官方依据： https://www.sqlite.org/pragma.html#pragma_auto_vacuum 和 https://www.sqlite.org/pragma.html#pragma_wal_checkpoint 。

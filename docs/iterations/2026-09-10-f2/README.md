## 本轮源码改动

### 有意义的批量查询

`crates/remote-hosts-code/src/observations.rs` 修复三处问题：

| 问题 | 处理 |
|---|---|
| 20 个小结果实际能装进 4 KiB，却因保守估算全部被省略 | 先保留实际 JSON 占位项，再按完整序列化后的真实长度装入结果；不再统一预扣 512 字节乘以项目数。 |
| 一个下载产物过期，使整批其它结果一起丢失 | 先完成整批所有者、设备和权限校验；取结果失败只标识对应原操作为 result_unavailable，其它有权限的结果保留。错误不回显私有 URL，也不会重新派发原任务。 |
| 高级单 ID 查询显式 max_bytes 没有生效 | 高级查询遵守预算，超出则明确 result_omitted；不带额外选项的旧单 ID 调用仍保留原结果形状。 |

新增三项回归在修复前确实失败：测试返回 download artifact unavailable、超过显式预算、20 个小结果被全部省略。原有九项观察回归通过。日志：`target/iteration-f1/observation-baseline.log`。新增用例保存在 `tests/observations_032.rs`。

这是一份等待发布的工作树修复，不是当前冻结线上版本已经修复的证明。批量查询、权限检查、进度游标和不重新执行原操作的设计继续保留。

### 不再让并行编辑使验收反复失效

新增 `scripts/source_snapshot.py`，按声明的源输入复制独立的普通文件，不使用硬链接或符号链接。复制时校验实际字节、文件状态和源清单，拒绝复制期间发生变化的输入；同时绑定可执行属性。已有目标不能覆盖，部分准备结果不发布为有效快照。

`check-code-source.py` 的回执新增 execution_root 与 snapshot_id。检查和构建可在副本内运行，原工作树后续编辑不会改变该副本；副本自己发生改动仍会使验证失效。这不是对任意用户代码的执行沙箱，也不是文件系统级瞬时全仓库事务。

首份快照的独立编译发现：旧验证清单漏掉了根目录 `migrations/`。`remote-hosts-db` 通过 `sqlx::migrate!("../../migrations")` 编译这些文件；缺失它们既无法从副本构建，也意味着原清单可能漏判 SQL 迁移变化。搜索当前源码还核对了 include_str/include_bytes 与相对路径的嵌入位置。输入清单现同时覆盖 migrations、fixtures、tests、assets、.sqlx 以及编译配置；crate 内资源随原目录整体纳入。动态构建脚本未来读取其它路径仍需要扩展显式输入范围。

首份有遗漏的副本 `032-f1` 及失败日志保留，不冒充有效构建候选，也没有原地补写它来改变其身份。
